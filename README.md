# `regimebench`

**Do cluster-validity indices recover the true number of market regimes?**

A controlled benchmark for regime-count selection on financial time series, testing
Silhouette, Davies–Bouldin, Calinski–Harabasz, AIC, BIC, BIC(N_eff), ICL, the Gap
Statistic and Prediction Strength against known ground truth, four null controls, and a
century of US daily returns.

Accompanying article: *Boundary Pinning in Cluster-Count Selection: A Controlled Benchmark
on Persistent, Heavy-Tailed Time Series* (under review, *Array*).

Archived release: [10.5281/zenodo.21981329](https://doi.org/10.5281/zenodo.21981329) — the
exact code that produced every reported result. `CITATION.cff` carries the citation
metadata; GitHub's "Cite this repository" reads it.

---

## What the benchmark reports

The headline is **two positive controls**, which benchmarks of this kind normally omit.
The *harness* control exploits the fact that the generators return the latent conditional
volatility `sigma_t`: clustering on it recovers the true partition exactly under HMM
emissions (ARI = 1.0000). The *criterion* control runs the identical criterion code on
well-separated i.i.d. Gaussian clusters, where every geometric index recovers `k*` in 100%
of replications and the Gap Statistic never answers `k=1`. Together they exclude both
classes of implementation error, and they are what license every negative result below.

Given both controls, no criterion tested recovers `k` reliably, and six of the ten do not
respond to it at all — raising the true `k*` from 2 to 4 moves their mean `k_hat` by at
most 0.42, against the 2.00 that tracking would require. They come to rest at a boundary
of their own candidate range: Silhouette at the floor (2.07 at every `k*`),
Calinski–Harabasz at the ceiling in 100% of runs, the Gap Statistic at `k=1` on 99.6% of
regime-bearing series. The four GMM criteria do respond, at roughly half the required
slope and from an offset baseline, so their exact recovery never exceeds 39.4%.

A 2×2×2 ablation isolates why. **Temporal persistence has no main effect at all** — these
estimators are permutation-invariant, so autocorrelation has no channel through which to
reach them — but it interacts strongly with the feature window. **Skew and rolling-window
smoothing are each independently sufficient** to take recovery from 100% to 0%. What
governs recovery is therefore dwell time *relative to the window* and **realized** (not
intended) **separation**, which MS-GARCH compresses severely.

## Structure

```text
regimebench/          library
  generators/         MS-GARCH, HMM Student-t, SV+jump
  methods/            K-Means, GMM, HMM wrappers
  criteria/           validity indices, information criteria, Gap, Prediction Strength
  metrics/            ARI/NMI, recovery, Wilson intervals, dwell time
  reference/          Bry-Boschan / Pagan-Sossounov turning-point dating
  data/               Fama-French, FRED, Binance connectors with provenance + caching
experiments/          one runner per experiment, all wired into run_all.py
tests/                unit tests
tools/                manuscript integrity verifier and packaging scripts
```

## Reproducing everything

```powershell
uv sync                       # or: python -m pip install -e ".[dev]"
uv run python run_all.py
```

`run_all.py --list` prints the pipeline; `--from N` resumes; `--only N M` runs selected
steps. Every result, table and figure comes from this pipeline, as does the graphical
abstract.

Expect roughly 45–60 minutes end to end on eight cores. The slowest steps are the factor
grid and the Gap reference study; the criterion control is about 5 minutes and the mechanism
ablation about 25.

The final step is the integrity check:

```powershell
uv run python tools/verify_manuscript.py              # exits non-zero on drift
uv run python tools/verify_manuscript.py --self-test  # proves it catches injected drift
```

It parses every number out of the article's LaTeX source and asserts it against the CSV in
`experiments/output/` that produced it, so a re-run that changes a result fails the build
rather than silently disagreeing with the article. **The article source is not distributed
with this repository** — this repository is the benchmark, not the paper — so the step
detects the absent source and skips rather than failing. It is included because the pattern
is reusable: point `TEX` at your own manuscript and the same mechanism holds your paper to
your artifacts.

Every number the article reports is in `experiments/output/`, regenerated by the pipeline
above, so the artifacts remain checkable against the published article by hand.

## Using the library on your own series

The benchmark is one application of the package; the parts are usable independently.

### Select `k` on your own feature matrix

```python
import numpy as np
from regimebench.methods.clustering_wrappers import fit_kmeans, fit_gmm
from regimebench.criteria.k_selection import (
    compute_internal_indices, compute_gap_statistic, compute_prediction_strength,
)

X = my_features.reshape(-1, 1)          # (n_samples, n_features)

for k in range(2, 7):
    labels, info = fit_kmeans(X, k=k, random_state=42)
    print(k, compute_internal_indices(X, labels))

# Gap Statistic. Sweep `reference`, do not trust the default in isolation:
# 'uniform' is degenerate on a right-skewed feature and returns the smallest k.
k_hat, gaps = compute_gap_statistic(X, fit_kmeans, k_range=range(2, 7),
                                    reference="uniform")

k_ps, scores = compute_prediction_strength(X, k_range=range(2, 7), threshold=0.8)
```

`fit_gmm` and `fit_hmm` share the `(X, k, random_state) -> (labels, info)` signature;
`info` carries the log-likelihood and parameter count that
`compute_information_criteria` needs for AIC, BIC, BIC(N_eff) and ICL.

### Generate labelled regime-switching series

Each generator returns `(returns, states, sigma_t)` — the latent volatility path is what
makes the positive control possible.

```python
from regimebench.generators.ms_garch import simulate_msgarch

returns, states, sigma = simulate_msgarch(k=3, T=5000, persistence=0.95,
                                          vol_ratios=[1, 3, 10], random_state=42)
```

`simulate_hmm_t` and `simulate_sv_jump` are the Student-t HMM and the
stochastic-volatility-plus-jump null.

### Score a recovered partition

```python
from regimebench.metrics.evaluators import (
    compute_partition_quality, compute_recovery_metrics, wilson_interval,
)

compute_partition_quality(states, labels)        # ARI, NMI
compute_recovery_metrics(k_hats, k_true=3)       # exact-recovery rate, mean k_hat
wilson_interval(successes=27, n=30)              # binomial CI for a recovery rate
```

Before reading any selection result, run the same code on well-separated Gaussian
clusters — `experiments/run_criterion_control.py` is the template. Every negative result
in this benchmark is licensed by that control passing.

## Data and offline use

Raw downloads are cached to `data/raw/` as parsed CSV and logged in `data/provenance.json`
with source URL, timestamp, row count, date range and the SHA-256 of the upstream payload.
After one online run the whole pipeline reproduces offline from cache. The connectors
raise rather than silently substituting synthetic data; `allow_synthetic=True` must be
passed explicitly.

## Method coverage

Reported in the accompanying article:

| Family | Method | Criteria |
| --- | --- | --- |
| Geometric | K-Means | Silhouette, Davies–Bouldin, Calinski–Harabasz, Gap, Prediction Strength |
| Probabilistic | Gaussian Mixture | AIC, BIC, BIC(N_eff), ICL |
| Temporal | Gaussian HMM | AIC, BIC, ICL |

Every method the package implements is run, and every one appears in a reported table or
figure. There is no unrun code in `regimebench/methods/`. Every pair in the table is run
twice: once on the volatility feature (the benchmark) and once on well-separated Gaussian
clusters (`experiments/run_criterion_control.py`), so each reported failure has a matching
success on the data the criterion was designed for.
